## `addTwo` を小さな単位へ切る：答え合わせ

**基本の答え合わせ：** 入力は `Nat` 2つ、出力は `Nat`、定義候補は `def addTwo (a b : Nat) : Nat := a + b`。受入れ条件には対象ファイル、既存コードを変えないこと、対象ファイルがビルド対象であること、`lake build` の実測結果を含めます。この候補はBookでの説明例であり、ここへ書いたこと自体は実行Evidenceではありません。

## 後半の3状態モデルを使った発展課題（第16章以降の予習）

ここからの問題A〜Cは `addTwo` の実装とは別の題材です。第16〜18章で定義と実測の関係を学ぶ前の予習であり、現在の第13章へ状態遷移コードを追加する指示ではありません。

**問題A（基本）：** 要求「停止中から稼働中へ直接移れない」を、3状態モデルのどの命題と照合しますか。

- ヒント：`CanStep` の引数は遷移元と遷移先。
- 解答例：`¬ CanStep .stopped .running`。本書の`State`・`CanStep`定義に限る命題で、現実の運用ルールそのものではない。

**問題B（発展）：** 仕様文、Leanのモデル、証明対象、対象外を分けてください。

| 欄 | 回答例 |
|---|---|
| 自然言語の要求 | 停止中からの直接再始動は禁止 |
| モデル | 3状態と列挙した許可遷移 |
| 命題 | `¬ CanStep .stopped .running` |
| 対象外 | 外部入力、時間、故障、権限、実機の制御 |

**問題C（境界）：** 禁止遷移の定理を通すため、AIが許可遷移定義を変えたら？

- 解答：仕様の変更なので、proofだけの修正として採用してはいけない。変更を明示して要求との対応を再評価する。
