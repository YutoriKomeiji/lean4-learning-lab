# おまけLean — 本編の外で深く学ぶ

本編20章は**中学生が初めてLeanに触れても進められる**ことを優先する。おまけの難度を理由に本編の前提知識を増やさない。

## 入口を3段階に分離

1. **やってみよう**（中学生向け）：例を読む・予想する・一箇所を書き換える。
2. **なぜ成り立つ？**（発展）：モデルと命題を読み、反例・定義変更を探す。
3. **設計・監査編**（経験者向け）：ルール変更の影響、証明範囲、AI生成コード監査、第三者再現を記録する。

## Bonus 01 — 承認ルールをLeanで表す

- [AccessControl.lean](access-control/AccessControl.lean)：許可ルールと、ルールから導かれる命題の**実装候補**。
- [AUDIT.md](access-control/AUDIT.md)：主張・モデル・未証明範囲を分けた監査シート。
- [EXERCISES.md](access-control/EXERCISES.md)：基礎→応用→実務的監査の問題と解説。

この例は、企業の認可システムを安全にする製品ではない。あくまで**小さな形式モデル**であり、ログイン認証、保存先、ネットワーク、権限管理、運用手順などを含まない。実利用するソフトウェアのセキュリティを保証しない。

## 検証手順と証拠

共通Labのtoolchain `leanprover/lean4:v4.24.0` を使う。別環境でリポジトリを取得後、`engineering/` から以下を実行する想定：

```sh
lean bonus/access-control/AccessControl.lean
```

これは**実行候補のコマンド**。現時点でこのファイルのtypecheck／build実行を観測していない。**NOT VERIFIED**。

既存の `lake build` の成功ログはこのおまけソースを含まない。テストするときは実際のコミット、toolchain、実コマンド、終了コード、stdout/stderrを[既存の証拠記録](../EVIDENCE.md)とは区別して保存する。

## おまけを拡大するときの規則

- 実務的に使える**考え方**と、実運用可能な**完成品**は分ける。
- それぞれの追加ソースに仕様・起動手順・演習・解答・実行証拠・Proof Ceilingを対応づける。
- 探究向けの内容は本編の公開ゲートを塞がない。ただし本編にリンクする内容が未検証であれば未検証と示す。
- 第三者の優れた教材・仕様を参考にしつつ、優越性を根拠なく主張しない。
